# Code style

## Go
- Format with `gofmt`. Code must pass `go vet ./...`.
- Return errors; don't panic. The one exception is generated code and `rt`, which use panics on purpose for `THROW` and `RESPOND` (design §4.6).
- Compiler errors are `diag.Diagnostic` values with a position and a hint. Never return a bare `fmt.Errorf` from the compiler to the user.
- Prefer table-driven tests. Language features are tested through golden files in `testdata/golden`.
- Keep `rt` small and fast. Generated code calls it on every operation, so avoid reflection on hot paths.
- Prefix stubs with `// TODO(task X.Y):`, using the task number from `tasks.md`.

## Generated Go
- Emit a `//line file.bas:N` directive before every statement.
- Mangle BASIC names: `b_<module>_<name>` in lowercase.
- Generated files start with `// Code generated by rip. DO NOT EDIT.`

## Error message tone
- Spooky but helpful: the classic `?KIND ERROR IN file:line`, then an em dash and a plain-language fix.
- Good: `?SYNTAX ERROR IN billing.bas:7 — expected THEN after IF condition`
- Good: `?UNDEFINED ERROR IN main.bas:12 — no function named CALCTAX; did you mean CALCTOTAL?`
- Bad: `unexpected token`. It has no location, no hint and no personality.
- HTTP error strings are ALL CAPS: `ROUTE NOT FOUND IN THIS REALM`, `INVOICE IS DEAD`.

## TypeScript (playground/web)
- Strict mode, function components, no `any`.
